# رادین – هسته API نسخه ۰٫۸

این بسته یک **پایه واقعی backend** برای تبدیل نمونه محلی فروشگاه به سامانه چندکاربره است. شامل API مبتنی بر Node.js/Express، دیتابیس PostgreSQL و Prisma است.

## امکانات این مرحله
- PostgreSQL با Docker Compose
- مدل‌های مدیر/کارمند، دسته‌بندی، محصول، تنوع کالا و گردش موجودی
- راه‌اندازی یک‌باره مدیر اصلی
- ورود با موبایل و رمز عبور و توکن JWT هشت‌ساعته
- نقش‌های OWNER و WAREHOUSE برای عملیات حساس کالا
- API عمومی کاتالوگ که قیمت عمده و بهای خرید را **اصلاً برنمی‌گرداند**
- ثبت محصول با چند تنوع، افزودن و ویرایش تنوع
- ثبت ورود، خروج و اصلاح موجودی در تراکنش دیتابیس
- اعتبارسنجی ورودی‌ها و مدیریت خطاهای یکتا بودن SKU/بارکد
- محدودیت تلاش ورود و راه‌اندازی اولیه در هر نمونه سرور
- جلوگیری از فروش هم‌زمان بیش از موجودی با کاهش شرطی و اتمیک
- جلوگیری از ایجاد هم‌زمان دو مدیر اصلی با قفل تراکنشی PostgreSQL

## پیش‌نیاز
- Node.js 20 یا بالاتر
- Docker و Docker Compose
- دسترسی نصب بسته‌های npm

## راه‌اندازی محلی
1. این پوشه را از ZIP خارج کنید.
2. `.env.example` را به `.env` کپی کنید و رمزها را عوض کنید.
3. رمز PostgreSQL در `docker-compose.yml` را با مقدار داخل `DATABASE_URL` هماهنگ کنید.
4. اجرا کنید:

```bash
docker compose up -d
npm install
npm run db:generate
npm run db:migrate
npm run dev
```

API روی `http://localhost:4000` اجرا می‌شود. سلامت سرویس:
`GET /health`

## ساخت مدیر اصلی
درخواست `POST /auth/bootstrap-owner` فقط یک بار مجاز است:

```json
{
  "secret": "همان OWNER_BOOTSTRAP_SECRET داخل فایل env",
  "mobile": "09xxxxxxxxx",
  "fullName": "مدیر رادین",
  "password": "یک رمز طولانی و غیرقابل حدس"
}
```

پس از ساخت مدیر، کلید راه‌اندازی را از محیط اجرا حذف یا تعویض کنید.

## ورود
`POST /auth/login`

```json
{"mobile":"09xxxxxxxxx","password":"رمز مدیر"}
```

توکن برگشتی را در درخواست‌های مدیریتی با هدر زیر ارسال کنید:
`Authorization: Bearer TOKEN`

| روش | مسیر | دسترسی |

| GET | `/auth/me` | کارمند واردشده |

| GET | `/admin/products` | OWNER / WAREHOUSE |

## نکات امنیت و محدودیت‌ها
- این نسخه پایه توسعه است، نه سرویس آماده انتشار عمومی.
- برای استقرار اینترنتی باید HTTPS، محدودیت نرخ درخواست ورود، سیاست پشتیبان‌گیری و بازیابی، مدیریت نشست/ابطال توکن، ثبت لاگ ممیزی، مدیریت اسرار و آزمون امنیتی اضافه شود.
- در این مرحله OTP، بازیابی رمز، آپلود امن تصویر، پرداخت آنلاین، چک‌ها، وفاداری و اتصال Flutter/پنل وب هنوز پیاده نشده‌اند. ثبت درخواست سفارش اولیه اضافه شده است.
- توکن فعلاً JWT هشت‌ساعته است و سازوکار ابطال فوری ندارد.
- محدودکننده تلاش‌ها در این نسخه حافظه‌ای و مختص یک پردازه است؛ برای چند نمونه سرور باید به Redis یا ذخیره‌ساز مشترک منتقل شود.
- در ثبت `ADJUSTMENT`، فیلد `quantity` موجودی نهایی موردنظر است، نه مقدار افزایش/کاهش.
- قیمت‌ها در دیتابیس BigInt ذخیره می‌شوند تا دقت مبلغ حفظ شود؛ پاسخ API آن‌ها را به شکل رشته برمی‌گرداند.
- رمز دیتابیس نمونه را در محیط واقعی حتماً تغییر دهید و پورت دیتابیس را عمومی نکنید.

## وضعیت آزمون
فایل‌های JavaScript با `npm run check` از نظر نحو بررسی می‌شوند. آزمون‌های پایه با `npm test` اجرا می‌شوند. اجرای واقعی migration و تست یکپارچه نیازمند نصب npm و اجرای PostgreSQL است؛ صرف تحویل ZIP به معنی اجرای سرور یا تست اتصال دیتابیس نیست.


## نسخه ۰٫۸ – سفارش مشتری
- مدل‌های Customer، Order و OrderItem اضافه شده‌اند.
- `POST /public/orders`: دریافت مشخصات تحویل و شناسه تنوع/تعداد؛ قیمت از دیتابیس خوانده می‌شود و مبلغ ارسالی از مرورگر پذیرفته نمی‌شود.
- سفارش ابتدا `PENDING_REVIEW` و `UNPAID` است؛ این نسخه درگاه پرداخت ندارد.
- هنگام ثبت سفارش، موجودی در یک تراکنش کم و گردش انبار ثبت می‌شود. هنگام لغو سفارش قبل از ارسال، موجودی برمی‌گردد.
- `GET /admin/orders`: مشاهده ۱۰۰ سفارش آخر برای کارکنان مجاز.
- `PATCH /admin/orders/:id/status`: تغییر وضعیت طبق مسیر مجاز؛ فقط مدیر اصلی و مسئول سفارش.

پس از دریافت این نسخه، در محیط توسعه اجرا کنید: `npx prisma generate` و سپس `npx prisma migrate dev --name customer_orders`. پیش از انتشار عمومی، بکاپ دیتابیس و بازبینی امنیتی و تست یکپارچه الزامی است.
